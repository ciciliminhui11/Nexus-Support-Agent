# 功能规格说明：意图识别（三层漏斗）

**功能分支**：`006-intent-recognition`

**创建日期**：2026-08-29

**状态**：草稿

**输入**：用户描述："用户问题意图识别（三层漏斗：前置校验规则层 → 小模型识别层 → 大模型兜底层），识别意图为产品咨询/售后/闲聊/投诉四类，结果标注 message.intent_label 并按意图路由分发。前置校验层零模型推理：文本归一化 + AC自动机关键词匹配（最长匹配+词边界）+ DFA句式模板匹配；小模型使用 DeepSeek-R1-0528-Qwen3-8B，正向校准与反向校准，高/低双阈值机制（≥高阈值直接输出、中段反问澄清、<低阈值流转大模型）；大模型兜底用 Few-shot + JSON 结构化输出。模型 API 密钥等配置通过环境变量占位，用户后续填写。"

## 识别链路概述

本特性的核心是一条**三层漏斗式意图识别链路**，按「每一层处理不了才流转到下一层」的顺序执行，越往后算力成本越高：

1. **前置校验层（规则层，零模型推理）**：先用关键词匹配 + 句式模板匹配高频固定意图。命中即输出意图、不消耗任何模型算力；匹配前做文本归一化，命中时采用最长匹配与词边界校验。
2. **小模型识别层（轻量模型推理，核心识别层）**：规则层未命中时，调用轻量小模型对输入分类，并通过正向校准（标注数据约束）与反向校准（负样本校验）抑制误判；置信度采用高/低双阈值判定。
3. **大模型兜底层（高算力，最后防线）**：小模型完全拿不准（低于低阈值）或反向校验不通过时，用大模型 + Few-shot 样例兜底识别，强制 JSON 结构化输出保证下游可解析。

识别结果统一为「意图 + 置信度 + 来源层」，写入会话消息的意图标签字段，并按意图路由到对应处理链路。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 高频/固定问法零成本拦截（优先级：P1）

用户输入包含明确关键词或固定句式（如"我要投诉"、"帮我查询一下退款政策"、"怎么退换货"），系统在前置校验层直接识别出意图，**不调用任何模型**，毫秒级完成并标记意图标签。

**优先级理由**：三层漏斗的经济性根基是"能省则省"——高频关键词与固定句式在客服请求中占比高，规则层零模型推理、零算力成本、最低延迟，是最先要落地、也最容易独立验证的一层，故为 P1。

**独立测试**：配置一套关键词库与句式模板后，输入命中规则的固定问法，可独立验证：不调用任何模型即输出意图、消息带意图标签、并按路由分发到对应处理。

**验收场景**：

1. **假如** 用户输入"我要投诉你们的服务质量"且词库包含"投诉"，**当** 提交问题，**那么** 前置校验层直接命中「投诉」意图，不调用任何模型，消息记录标注 `intent_label=投诉`。
2. **假如** 用户输入符合句式模板的固定问法（如"帮我查询……"、"取消订单……"），**当** 提交，**那么** 句式模板匹配命中，直接输出对应意图并路由，不进入模型层。
3. **假如** 用户输入同时命中多个关键词（如"投诉"与"咨询"同时出现），**当** 匹配，**那么** 采用最长匹配策略，取更长命中结果作为最终意图，而非任意子串。

---

### 用户故事 2 - 常规口语表达由小模型识别 + 双阈值判定（优先级：P2）

用户用口语化、非固定句式表达（如"这玩意儿能不能七天无理由"、"你们家售后怎么弄的"），规则层未命中，交由小模型（DeepSeek-R1-0528-Qwen3-8B）分类。置信度 ≥ 高阈值直接出意图；中段置信度反问用户澄清后重判；低于低阈值放弃小模型结果。

**优先级理由**：小模型是流量主力，承担绝大多数规则覆盖不到的自由表达，但其正确性依赖校准与阈值工程，配置成本高于规则层，故为 P2。

**独立测试**：配置好小模型 API 后，输入非固定句式问题，可独立验证高/中/低置信度三条路径的判定行为，以及反向校准拦截行为。

**验收场景**：

1. **假如** 规则层未命中且小模型置信度 ≥ 高阈值，**当** 处理该输入，**那么** 直接输出识别意图，交给下游路由并标注，不进入大模型层。
2. **假如** 小模型置信度落在【低阈值，高阈值）区间，**当** 处理该输入，**那么** 系统反问用户澄清（"请问你是想要 X 还是 Y？"），收集更多信息后重判；重判仍不达标时按配置重试小模型一次。
3. **假如** 小模型置信度 < 低阈值，**当** 处理该输入，**那么** 放弃小模型结果，流转到大模型兜底层。
4. **假如** 小模型输出了某个意图但反向校准判定该输入并不真正符合该意图特征（负样本命中），**当** 校验，**那么** 拒绝该预测结果，不采信小模型输出，视同拿不准流转下一层。

---

### 用户故事 3 - 歧义/新说法由大模型兜底（优先级：P3）

小模型完全拿不准的歧义、新说法、复杂混合表达，由大模型通过 Few-shot 样例 + JSON 结构化输出兜底识别，保证识别结果 100% 可被下游解析。

**优先级理由**：这是最后一层防线，只在少数输入触发，算力成本最高，放在规则层与小模型层之后落地，故为 P3。

**独立测试**：配置好大模型 API 后，输入模糊歧义问题，可独立验证返回 JSON 结构化意图结果；模型不可用时验证降级行为。

**验收场景**：

1. **假如** 小模型低置信度放弃（或反向校准拒绝），**当** 流转大模型，**那么** 大模型依据 Few-shot 样例与意图清单输出 JSON 结构化结果（意图 + 置信度），禁止自由文本闲聊。
2. **假如** 大模型返回内容无法解析、为空或调用失败（超时/限流），**当** 处理，**那么** 返回降级结果（意图标记为「未识别」+ 默认路由），不阻断用户提问主流程。
3. **假如** 输入是四类意图之外的混合或离题表达，**当** 兜底识别，**那么** 归入最相近意图，或按配置的兜底策略标记处理。

---

### 边界情况

- 输入为空、纯标点、纯表情——前置校验层与各模型层的行为与降级路径。
- 输入恰好在 500 字上限边界（超长在 001 特性已被拒绝，本特性不重复处理）。
- 输入同时包含多个意图特征（如"投诉"+"咨询"同现）——规则层冲突裁决与最长匹配。
- 歧义表达（如"能退吗"：产品咨询 or 售后）——中段置信度触发澄清反问。
- 关键词为任意子串而非完整语义片段（如"投诉"出现在"投诉咨询中心"中）——词边界校验。
- 小模型/大模型 API 超时、限流（429）、密钥未配置——降级为「未识别」+ 默认路由，不影响提问。
- 用户澄清反问后仍未消除歧义——最终降级策略。
- 闲聊意图误入知识库检索——路由必须保证闲聊不检索。

## 需求 *(必填)*

### 功能需求

**前置校验层（规则层）**

- **FR-001**：系统 MUST 在规则层匹配前对用户输入执行文本归一化（去除空格与特殊符号、繁简转换、常见形近字纠错），归一化结果作为匹配输入，原始输入保留用于展示与入库。
- **FR-002**：系统 MUST 使用多模式串匹配（AC 自动机）对关键词集合同时匹配，命中即输出对应意图；多条命中时采用**最长匹配策略**，取更长命中结果。
- **FR-003**：系统 MUST 在关键词匹配时执行**词边界校验**，只匹配完整语义片段，不匹配任意子串。
- **FR-004**：系统 MUST 通过句式模板匹配识别固定句式（如"帮我查询X"、"取消订单X"），覆盖强固定句式问法。
- **FR-005**：规则层命中且无意图冲突时，系统 MUST 直接输出意图并终止本次识别流程，**不调用任何模型**。

**小模型识别层**

- **FR-006**：规则层未命中时，系统 MUST 调用小模型（DeepSeek-R1-0528-Qwen3-8B）对输入进行意图分类。
- **FR-007**：系统 MUST 对规则层未命中的输入执行**正向校准**（基于标注数据的分类约束）与**反向校准**（负样本校验：判定该输入是否真正符合输出意图的特征，不符即拒绝该预测）。
- **FR-008**：系统 MUST 对小模型分类结果设置**高/低双阈值**：置信度 ≥ 高阈值 → 直接输出意图；低阈值 ≤ 置信度 < 高阈值 → 反问用户澄清（或按配置重试小模型）；置信度 < 低阈值 → 放弃小模型结果，流转大模型兜底。

**大模型兜底层**

- **FR-009**：系统 MUST 在小模型放弃时调用大模型兜底识别，Prompt 必须携带**多条 Few-shot 样例**（用户输入 → 输出意图）与可用意图清单。
- **FR-010**：系统 MUST 强制大模型输出 **JSON 结构化结果**（意图 + 置信度），禁止自由文本闲聊，保证下游可解析；解析失败时返回降级结果。

**标注与路由**

- **FR-011**：系统 MUST 将最终识别结果（意图 + 来源层）写入会话消息的意图标签字段（`message.intent_label`），供会话详情与后台统计使用。
- **FR-012**：系统 MUST 按识别意图路由分发：产品咨询/售后 → RAG 问答链路；闲聊 → 不检索知识库直接友好回复；投诉 → 转人工客服提示。
- **FR-013**：系统 MUST 在识别流程异常（模型超时/限流/密钥未配置）时降级为「未识别」意图 + 默认路由，不影响用户提问主流程。

**配置**

- **FR-014**：系统 MUST 支持模型 API 密钥、BaseURL、模型名、双阈值等参数通过环境变量/系统配置读取，**禁止硬编码**；提供 `.env.example` 占位模板，真实密钥由用户后续填写且不提交仓库。

*未明确项已在「假设」中给出默认值，无需 [NEEDS CLARIFICATION]。*

### 关键实体

- **IntentResult（识别结果）**：一次识别流程的产出；含意图（产品咨询/售后/闲聊/投诉/未识别）、置信度、来源层（规则/小模型/大模型）、原始输入与归一化输入。
- **IntentRouter（意图路由）**：意图 → 处理 Handler 的映射；产品咨询/售后 → RAG 问答，闲聊 → 闲聊回复，投诉 → 转人工提示，未识别 → 默认路由。
- **IntentRecognitionConfig（识别配置）**：关键词库、句式模板、双阈值（高/低）、模型调用参数；部分敏感参数（密钥）经环境变量注入。
- **Message.intent_label（消息意图标签）**：复用 001/004 消息表已设计的意图标签字段，本特性写入并消费。

## 成功标准 *(必填)*

### 可度量结果

- **SC-001**：规则层可覆盖的高频关键词/固定句式输入，100% 不调用任何模型即完成识别，识别附加延迟 < 10ms。
- **SC-002**：小模型高阈值输出的意图识别准确率 ≥ 95%（对照标注评测集）。
- **SC-003**：反向校准拦截后，小模型低置信度输入被强行误标为某类意图的比例 < 2%（防"乱打标签"）。
- **SC-004**：需大模型兜底的输入，100% 返回可被下游解析的 JSON 结构化结果（含「未识别」降级）。
- **SC-005**：产品咨询/售后/闲聊/投诉四类意图均可被识别，识别结果 100% 写入消息意图标签。
- **SC-006**：规则层与小模型命中路径的识别附加延迟 ≤ 50ms（用户无感）；大模型兜底识别在 3 秒内完成并返回可解析结果。
- **SC-007**：闲聊与投诉意图 100% 不进入知识库检索（路由行为正确）。

## 假设

- 小模型与大模型通过 HTTP API 调用；API 密钥、BaseURL、模型名经环境变量配置，用户负责填写真实密钥（`.env.example` 提供占位，真实密钥不提交仓库）。
- 小模型默认使用 DeepSeek-R1-0528-Qwen3-8B；大模型默认使用 DeepSeek 系列更大模型（均可配置）。
- 关键词库、句式模板、双阈值参数为可配置项；v1 内置一套默认词库与阈值基线，供联调校准。
- 意图标签写入 `message.intent_label`（001/004 消息表已设计该字段，本特性为消费者）。
- 闲聊与投诉采用模板/轻量回复，不进入 RAG 检索；产品咨询与售后走 RAG 问答链路（依赖 001 特性）。
- 正向校准标注集与反向校准负样本库为可配置数据；v1 内置一组基础样例，后续用真实流量扩充。
- 识别失败/模型不可用时降级为「未识别」意图 + 默认路由，不影响用户提问主流程（宪法原则：主链路可读可控、不因加分特性拖垮核心问答）。
