# 功能规格说明：RAG 智能问答链路

**功能分支**：`001-rag-qa`

**创建日期**：2026-08-29

**状态**：草稿

**输入**：用户描述："核心 RAG 问答链路：输入校验（长度、每日次数配额）、多轮上下文、Query 向量化、向量检索与阈值过滤、Prompt 组装、LLM 流式调用、SSE 流式返回带引用来源、空检索兜底、异常捕获（LLM 超时 / API 限流）"

## 用户场景与测试 *(必填)*

### 用户故事 1 - 用户提问并获得带来源的流式回答（优先级：P1）

用户登录后，在一个会话中提出一个问题，系统实时流式返回回答，回答末尾附带引用来源（文档名称 + 片段摘要）。

**优先级理由**：这是 RAG 系统的核心价值 —— 让用户得到基于知识库的可信回答。没有它，整个系统不成立，故为 P1。

**独立测试**：知识库有一条已就绪文档，用户发起提问，可独立验证：收到流式 token、回答尾部出现 `meta` 引用来源事件、会话已保存问答记录。

**验收场景**：

1. **假如** 用户已登录且有有效会话，知识库存在就绪文档，**当** 用户提交一个 500 字以内的正常问题，**那么** 后端以 SSE 流式逐块返回 `data` token，结束时返回 `finish` 事件，且 `meta` 事件携带该问题命中的文档名称与片段摘要。
2. **假如** 知识库检索到多个相关片段，**当** 生成回答，**那么** 回答严格限定在检索片段范围内，且所有引用来源均来自命中的知识库文档。
3. **假如** 回答完整流式输出后，**当** 会话结束，**那么** 用户提问与 AI 完整回答均被持久化，可在会话详情中查看历史。
4. **假如** 用户问题与知识片段无语义重叠但有关键词命中（如口语提问、品牌/型号/货号精确匹配），**当** 提交提问，**那么** 向量路被阈值过滤后 BM25 路仍能召回片段并给出带来源回答（混合检索补齐关键词召回）。
5. **假如** 检索到多个候选片段且已安装 Reranker 模型，**当** 提交提问，**那么** `meta` 引用来源按精排相关性排序（语义相关但业务无关的片段被压后）；未安装/加载失败时 `meta` 顺序回落融合序且链路正常。

---

### 用户故事 2 - 多轮对话上下文保持（优先级：P2）

用户在同一会话内连续追问，系统自动携带最近 N 轮历史，使回答能引用前文。

**优先级理由**：多轮对话是客服场景的标配，但可在单轮可用后再增强，故为 P2。

**独立测试**：在同一个会话连续提出两条相关的问题，验证第二条回答能理解第一条的语境，且请求体携带最近 N 轮历史。

**验收场景**：

1. **假如** 同一会话已有若干轮历史消息，**当** 用户发起新一轮提问，**那么** 请求携带最近 N 轮（N 可配置）历史上下文，回答能基于前文语境生成。
2. **假如** 历史 + 检索内容总长度超过上下文上限，**当** 组装 Prompt，**那么** 执行截断策略：优先丢弃最早历史，保留并（如过长）摘要压缩知识片段，而非整体丢弃知识。

---

### 用户故事 3 - 边界与异常情况下的弹性处理（优先级：P3）

当输入超长、配额耗尽、检索为空、LLM 超时或限流时，系统给出明确且友好的处理而不是报错崩溃或编造内容。

**优先级理由**：这些是保障系统可用性的工程边界，在核心链路可用后补充，故为 P3。

**独立测试**：分别构造 501 字问题、当日第 101 次提问、检索无命中、模拟 LLM 超时/429，逐一验证系统行为符合约定。

**验收场景**：

1. **假如** 用户提出问题长度超过 500 字，**当** 提交，**那么** 被拒绝并提示长度上限，不进入生成流程。
2. **假如** 用户当日提问次数已达限制，**当** 再次提问，**那么** 返回配额耗尽提示，不进入生成流程。
3. **假如** 混合检索两路均无有效片段（向量相似度低于阈值且 BM25 闸门不命中），**当** 处理该提问，**那么** 不调用生成，返回固定兜底话术（`抱歉，知识库中没有找到相关信息，请换个方式提问或者联系人工客服。`）且 **不编造** 内容。
4. **假如** LLM 调用超时或返回限流错误（如 429），**当** 出现该异常，**那么** 以 SSE `error` 事件推送友好错误信息，并对会话给出明确失败反馈（不发空响应、不静默结束）。

---

### 边界情况

- 用户问题恰好 500 字（边界值应通过），501 字应被拒绝。
- 单条问题全部是非相关主题、知识库无任何可能命中 —— 必须触发兜底话术而非乱答。
- 历史消息本身超长、知识片段超长、两者合计超上下文上限 —— 应对最长输入与混合超长场景给出可预期截断行为。
- LLM 返回空内容、仅返回部分 token、或中途断流 —— 系统应判定为失败并给出错误事件。
- 同一问题被反复提交、请求并发到达 —— 应保证消息记录与配额计数的一致性（不重复计数、不重复入库）。
- 知识库内容为 0（无任何就绪文档）时的提问 —— 应视同检索为空走兜底。
- 仅含功能字（如「今天的天气怎么样」）的提问与无关文档共享的只是「的/天/么」等非显著词 —— BM25 显著词闸门应拦截，不得因功能字产生关键词假阳性而破坏空检索兜底。
- Reranker 模型未安装 / 权重下载失败 / 推理抛异常 —— 应回退 RRF 融合序，服务不挂、回答仍带来源。

## 需求 *(必填)*

### 功能需求

- **FR-001**：系统 MUST 校验单条问题长度不超过 500 字；超长时拒绝并返回明确提示，不进入生成。
- **FR-002**：系统 MUST 在每次提问前校验用户当日已用次数是否达到上限（默认 100 次/用户/天，可配置）；超限时拒绝并返回配额耗尽提示。
- **FR-003**：系统 MUST 在问答请求中携带当前会话最近 N 轮历史消息（N 可配置），作为上下文输入。
- **FR-004**：系统 MUST 采用混合检索召回知识片段：向量语义检索（Chroma 余弦相似度，按阈值过滤）与 BM25 关键词检索（jieba 分词，显著词闸门）双路召回，经 RRF（Reciprocal Rank Fusion）融合排序形成粗筛候选池（`rag_candidate_k`），按 `rag_top_k` 召回候选送入后续链路。
- **FR-005**：系统 MUST 在检索无有效片段时不调用生成，直接输出固定兜底话术，并 **禁止** 模型编造内容。
- **FR-006**：系统 MUST 组装 System Prompt + 检索知识片段（带编号与来源）+ 历史对话 + 用户问题送入 LLM，并要求回答仅基于所给知识。
- **FR-007**：系统 MUST 以 SSE 流式逐块返回生成内容，**禁止** 全部生成完成后一次性返回。
- **FR-008**：系统 MUST 在回答中附带引用来源（文档名称 + 片段摘要），通过 SSE `meta` 事件下发。
- **FR-009**：系统 MUST 定义统一 SSE 事件协议：`data`（token）、`meta`（引用来源）、`finish`（结束）、`error`（错误）。
- **FR-010**：系统 MUST 捕获 LLM 调用超时与 API 限流（如 429）异常，以 SSE `error` 事件返回友好错误，不静默结束。
- **FR-011**：系统 MUST 在上下文总长度超限时执行截断策略：优先丢弃最早历史，保留并按需压缩知识片段，而非丢弃知识。
- **FR-012**：系统 MUST 在会话结束时持久化用户提问消息与 AI 完整回答，供会话详情与历史查询使用。
- **FR-013**：系统 MUST 在输出完成后执行来源后校验：检出内容超出知识库范围的，标记提示而非静默放行。
- **FR-014**：系统 MUST 对 RRF 融合后的粗筛候选池（`rag_candidate_k`）执行 Reranker 精排（Cross-Encoder 对「问题-片段」对打分），取 `rag_top_k` 送入 LLM；Reranker 模型未安装 / 加载失败 / 推理异常时 MUST 回退 RRF 融合序，服务不中断（可插拔降级）。

*未明确项已在「假设」中给出默认值，无需 [NEEDS CLARIFICATION]。*

### 关键实体

- **Session（会话）**：一次用户问答的对话集合；包含 user_id、标题、创建时间；承载多轮历史上下文。
- **Message（消息）**：会话内一条问答记录；含 role（user/ai）、content、intent_label、reference_source（JSON 引用来源）、create_time。
- **KnowledgeDoc（知识库文档）**：已入库文档元数据；含 doc_name、状态（处理中/就绪/失败）；其切片经向量索引后供检索。
- **ContentChunk（知识切片）**：文档切分后的片段；含文本、向量、关联文档 id（doc_id）、来源片段摘要。
- **UserQuotaDaily（每日提问计数）**：记录用户当日已用提问次数，用于 FR-002 配额校验。

## 成功标准 *(必填)*

### 可度量结果

- **SC-001**：单条不超过 500 字、配额内的提问，从提交到首个回答 token 的首字延迟在 3 秒以内（用户无明显等待感知）。
- **SC-002**：回答支持流式，用户在生成完成前即可看到逐步输出的文字，而不是等待整段结果。
- **SC-003**：100% 带知识内容的有效回答附带引用来源（文档名称 + 片段摘要），可被用户核验。
- **SC-004**：检索无命中的提问 100% 返回兜底话术，模型编造内容的检出率为 0（通过来源后校验保证）。
- **SC-005**：LLM 超时或限流时，用户在 5 秒内收到明确的错误提示，而非无响应或静默中断。
- **SC-006**：多轮会话中，基于前文语境的追问回答准确率不低于单轮平均水平（验证上下文携带有效性）。
- **SC-007**：上下文超长时，系统仍能基于保留的知识片段给出有效回答，而非因截断丢失关键知识。
- **SC-008**：送入 LLM 的片段经混合检索（向量 + BM25 + RRF 融合）+ Reranker 精排后，相关性不弱于单路向量检索；关键词精确匹配（品牌/型号/货号）可被 BM25 路召回；Reranker 的排序效果可通过注入假精排器在集成测试中断言 `meta` 顺序验证。

## 假设

- 用户已通过注册/登录获得有效身份（JWT 鉴权为另一个特性，本特性假定调用方已鉴权）。
- 知识库文档已完成解析并向量化入库（知识库管理为另一个特性，本特性假定存在就绪文档）。
- 检索与 LLM 调用均在服务端执行，前端不直接调用模型 API（遵循宪法原则三）。
- 相似度阈值、top-k、上下文轮数 N、每日配额上限等参数通过系统配置读取，默认值：阈值按可校准基线、top-k 可配、N 可配、配额默认 100。
- 文本切分策略与检索参数的具体取值（chunk_size、overlap、top-k、阈值）为待细化项，属于后续实现调整范围，不影响本规格的验收行为。
- 移动端与生产级向量库/对象存储切换不在本特性范围内（见宪法「开发流程与质量门槛」的组件切换迁移要求）。
- 意图识别、追问建议、多知识库路由、知识冲突检测等加分项不在本特性范围内；Reranker 精排（FR-014）在本特性范围内，但依赖模型安装，未安装/加载失败时自动降级为 RRF 融合序，不影响主链路。
