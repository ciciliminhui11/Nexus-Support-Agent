# 研究记录：会话与消息

**日期**：2026-08-29 | **特性**：[spec.md](spec.md)

本文件记录 Phase 0 对技术上下文 unknowns / 依赖 / 集成的研究结论，统一为「决策 / 理由 / 备选方案」。

## 1. 默认标题策略（FR-006）

- **决策**：创建会话时 `title` 置「新会话」；首条用户消息写入后，若标题仍为「新会话」，则用首条消息前 20 字符 + 「…」作为摘要标题（截断不拆分代理字符）。
- **理由**：FR-006 要求「标题由系统默认生成（新会话 或 首条消息截断摘要）」；首问即摘要比统一「新会话」更有辨识度，且实现简单、无额外 AI 调用（服务端纯文本处理，符合成本与速度要求）。
- **备选方案**：创建时用 LLM 生成标题 → 增加延迟与成本，违反 SC-001（2 秒内创建）；仅固定「新会话」→ 满足最低要求但列表辨识度差；标题编辑 → 规格假设明确为后续增强。

## 2. 数据隔离实现（FR-004 / SC-005）

- **决策**：所有会话/消息端点经 `get_current_user` 注入当前用户；列表查询 `WHERE user_id = :current_user_id`；详情/消息查询按 `session.id` 查得后断言 `session.user_id == current_user.id`，不满足即返回 404（不泄露会话存在性）。
- **理由**：FR-004/SC-005 要求跨用户访问 100% 拒绝；归属断言与列表过滤双保险；对他人会话返回 404 而非 403，避免泄露会话 ID 是否有效（与 001 的 `session_forbidden` 语义一致，可统一为 403；详见契约）。
- **备选方案**：仅前端隐藏入口 → 服务端无防护，违反合规；详情仅 403 不查归属 → 无法保证「列表过滤 + 详情断言」一致。

## 3. 分页策略（FR-009 / 边界：消息量大）

- **决策**：历史消息用游标/偏移分页：默认 `page=1&page_size=20`（`message_page_size` 可配置，上限 100）；按 `(create_time, id)` 稳定排序（同秒消息按 id 保证次序不重复不遗漏）；会话列表按 `create_time DESC` 分页（`page_size` 默认 20）。
- **理由**：SC-003 要求按时间完整有序返回；`(create_time, id)` 复合排序消除同时间戳乱序（边界要求消息写入并发）；游标分页在大数据量下稳定，偏移分页 v1 足够（单用户会话量级可控）。
- **备选方案**：一次性全量返回 → 消息量大阻塞展示（违反边界「不阻塞展示」）；仅按 create_time 排序 → 并发写入同秒消息次序不稳定。

## 4. 与 001-RAG 的读写联动（FR-005 / FR-008）

- **决策**：Message 的「写入」由 001 在问答流结束后完成（user 提问 + ai 回答，带 reference_source）；004 提供 `history.py` 的「最近 N 轮读取」（`ORDER BY create_time DESC LIMIT N` 再倒序返回）与详情分页查询；两者共享同一 Session/Message 表与模型定义。
- **理由**：FR-005 要求问答持久化到会话；FR-008 要求按配置读取最近 N 轮；单一数据源 + 明确读写边界（001 写、004 读）避免双写冲突，与 001 数据模型契约一致。
- **备选方案**：004 也写入消息 → 双写竞态、角色职责混乱；001 自建内存历史 → 重启丢失、与详情展示不一致（违反 SC-006 一致性）。

## 5. 会话容量与空会话处理

- **决策**：会话消息数不设上限，由分页承载；空会话详情返回空消息列表（HTTP 200，`items: []`）；列表为空返回空列表（`items: []`），前端据 `total=0` 展示创建引导。
- **理由**：规格边界明确「空列表/空会话正常返回不报错」；分页承载容量，避免单会话无限增长的内存/响应问题。
- **备选方案**：容量硬上限 → 与假设冲突（「不设上限，超出由分页承载」）；空会话报 404 → 违反边界要求。

## 6. 测试策略

- **决策**：pytest；单元测试覆盖会话 CRUD、默认标题生成、归属断言、分页排序；集成测试覆盖创建→问答→详情可见（联动 001 持久化）、跨用户访问拒绝（隔离）、同秒并发消息顺序、空会话/空列表。
- **理由**：宪法要求关键链路集成测试；数据隔离（SC-005）与持久化可见性（SC-004）是可度量合规项，必须集成验证。
- **备选方案**：仅单元测试 → 无法验证与 001 的持久化联动；缺少并发顺序测试 → 边界乱序风险。
